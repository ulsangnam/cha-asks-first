# 주행 화면 개편: 어두운 무대와 음성 효과

2026-11-12. 1차 접수(11-15) 전 개편. 기존 설계: `2026-11-03-cha-asks-first-app-design.md`.

## 목표

진행자가 말하고 운전자가 답하는 순간이 화면에서 보이게 한다. 말할 때는 음파, 들을 때는 퍼지는 동심원, 글자는 읽는 만큼 밝아지거나 한 글자씩 써진다. 분할 화면(내비 옆 절반 창)에서도 같은 화면이 나오고, 시연 영상은 운행 중인 내비와 이 앱을 함께 보여 준다.

## 지켜야 할 것

- Pleos Connect 주행 중 규칙: 문단 3줄 이하, 대비 4.5:1 이상, 시선을 끄는 애니메이션 금지.
  → 효과는 글자 뒤에 낮은 투명도로 천천히 움직이고, 깜빡임이 없다. 운전 집중(`Load.HIGH`)이면 즉시 멈춘다.
- 주행 중 화면 터치 0회. 주행 화면에는 지금처럼 누를 요소가 없다.
- 새 권한, 새 라이브러리를 추가하지 않는다.
- Window Policy: 앱 2개면 1:1 분할, 가로 전용이 아닌 앱은 가로·세로 레이아웃 모두 대응.

## 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 효과 방식 | 앱 상태로 그리는 합성 효과 (Compose Canvas) | TTS 오디오는 Pleos 서비스가 재생해 앱이 분석할 수 없고, STT 음량 콜백은 미확인 |
| 테마 | 앱 전체 다크 고정 | 빛나는 효과는 어두운 배경에서 보인다 |
| 분할 화면 | 폭에 따라 넓은/좁은 배치 | 가이드 요구. 플로팅(다른 앱 위 그리기)은 문서에 없는 권한이라 제외 |
| 효과 강도 | 글자 뒤 은은하게, 운전 집중이면 정지 | 주행 중 규칙 |
| 시연 영상 | 운행 중인 내비 + 이 앱 분할 화면 | 실제 주행 상황처럼 보이게 |

## 화면

색: `PleosDarkColors`. 주행 화면 배경만 남색 세로 그라데이션(앱 전용 색, 위 `#141B33` → 아래 `#0B1020`). 글자는 `textPrimary`(흰색), 흐린 글자는 흰색 35%.

넓은 창(폭 1000dp 이상):

```
[주행 중] [토크쇼] [도착까지 약 90분]                    ┌ 나 ──────────────┐
                                                        │ 운전자 답 (반투명) │
(●) 진행자 · 질문을 읽는 중                              └──────────────────┘

~~~~~~~~~~~~~~~ 음파 (화면 가로 전체, 세로 중앙) ~~~~~~~~~~~~~~~
        첫 차는 어떤 차였어요?          ← 질문, 음파 위에 겹침

Gleo 음성 엔진 · 온디바이스
```

좁은 창(폭 1000dp 미만): 칩 → 진행자 표시 → 음파(높이 축소) → 질문(3줄 이하) → 답 말풍선 → 엔진 표시를 세로로 쌓는다.

동의 화면과 기록 화면은 같은 다크 색만 적용하고 효과는 없다.

## 효과

| 상태 | 효과 |
|---|---|
| 말하는 중 (`VoiceActivity.SPEAKING`) | Gleo 파랑·연보라 사인파 3겹. 진폭은 가운데가 크고 양 끝으로 0이 되는 포락선. 위상이 천천히 흐른다(한 주기 약 3초). 투명도 40% 이하, 같은 선을 굵기·투명도를 달리해 겹쳐 빛나는 느낌을 낸다 |
| 듣는 중 (`LISTENING`) | 청록(앱 전용 `#4FC3D9`) 동심원. 1.2초마다 하나 생겨 3.6초 동안 반지름이 커지며 투명해진다. 동시에 최대 3개 |
| 대기 (`IDLE`) | 진폭이 매우 작은 가는 선 하나, 정지 |
| 운전 집중 (`Load.HIGH`) | 현재 모양 그대로 멈추고 회색(`textQuaternary`)으로 바뀐다 |

움직임은 초당 3회 미만으로 바뀌고, 밝기가 깜빡이지 않는다.

## 글자

- 진행자 질문: 지금처럼 문장 전체를 흐리게 먼저 보여 주고, 읽은 만큼 밝게 한다. 진행 정도는 기존 추정 `700ms + 150ms × 글자 수`.
- 운전자 답: `UiState.driverLine`이 바뀌면 말풍선에 45ms마다 한 글자씩 나타난다. 커서는 없다. 같은 문장이면 다시 써지지 않는다.
- 운전 집중이면 질문의 밝힘 진행은 지금처럼 0으로 돌아가 흐리게 보인다.

## 코드 구조

| 파일 | 내용 |
|---|---|
| `ui/effects/EffectMath.kt` | 순수 함수. `waveSample(x, phase, layer)`(파형 y값), `waveEnvelope(x)`, `rippleState(elapsedMs, index)`(반지름 비율·투명도), `revealCount(elapsedMs, length, perCharMs)` |
| `ui/effects/VoiceEffects.kt` | `SpeakingWave(frozen, modifier)`, `ListeningRipples(frozen, modifier)`, `IdleLine(modifier)`. 시간은 `withFrameMillis`로 받고, `frozen`이면 마지막 시각에서 멈춘다. 앱 전용 무대 색 상수도 여기 둔다 |
| `ui/Screens.kt` | `DrivingScreen`을 `BoxWithConstraints`로 넓은/좁은 배치로 나눈다. `DriverBubble`에 타자 효과. `HostOrb`는 작은 표시로 유지 |
| `ui/theme/PleosTheme.kt` | `PleosTheme(darkTheme: Boolean = isSystemInDarkTheme())` 인자 추가 |
| `ui/MainActivity.kt` | `PleosTheme(darkTheme = true)` |

`Orchestrator`와 `UiState`는 바꾸지 않는다. 필요한 값(`voice`, `speakingStartedAt`, `currentLine`, `driverLine`, `load`)이 이미 있다.

## 시연 영상: 운행 중인 내비와 함께

구현 전에 에뮬레이터에서 두 가지를 먼저 시험한다(스파이크, 30분 한도).

1. 분할 화면 띄우기: Window Policy의 창 바 탭·세 손가락 쓸기, 또는 `am start --windowingMode`, `cmd activity` 계열 명령으로 내비와 이 앱을 1:1로 띄운다.
2. 내비 경로 걸기: 내비 앱(`ai.umos.maps.android.navigation.app`)에서 목적지를 검색해 안내를 시작한다. 지도 타일이 비어 보이는 상태라 동작 여부를 모른다. 안내가 시작되면 NaviHelper가 실제 경로 신호를 받는지 `ChaAsks.Navi` 로그로 확인한다.

| 결과 | 영상 |
|---|---|
| 분할 성공 + 내비 경로 성공 | 내비 안내 화면 + 이 앱을 한 화면에 녹화. NaviHelper가 실제 경로를 받으면 경로 주입을 빼고 "실제 내비 신호"로 자막을 바꾼다 |
| 분할 성공 + 경로 실패 | 내비 지도 화면 + 이 앱. 경로는 지금처럼 주입하고 자막에 밝힌다 |
| 분할 실패 | 좁은 창 레이아웃을 `wm size`로 재현하고, 내비 화면은 장면 사이에 따로 보여 준다. 영상 자막에 "실차에서는 내비 옆 분할 화면"이라고 밝힌다 |

`make_demo_video.py`는 시작 시 분할 배치를 만드는 단계와, 결과에 맞춘 자막만 바꾼다.

## 확인

- 단위 테스트: `EffectMath`(포락선 양 끝 0·가운데 최대, 동심원 수명 끝에서 투명도 0, `revealCount` 경계값). 기존 27개 유지.
- 에뮬레이터 캡처: 넓은 창에서 말하는 중·듣는 중·운전 집중·답 써지는 중. 좁은 창(분할 또는 `wm size`)에서 같은 상태.
- 앱이 뒤에 있거나 분할 화면일 때 대화가 이어지는지 로그로 확인하고, 결과를 이 문서와 CLAUDE.md에 적는다.
- 끝나면 release APK 재빌드(`apk/TeamCAF_cha-asks-first_release.apk` 교체), 시연 영상 재녹화, 새 최종 커밋 해시를 접수용으로 알린다.
